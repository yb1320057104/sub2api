# Kilo 原生系统

本分支以 `yb1320057104/sub2api` 的 `main@a6f0bfcd447721308028160be36c97c8e4f57a21` 为基线，加入 Kilo 账号接入、订阅与身份生命周期、网关协议及独立执行器。功能登记为 PK-078，保留 PK-028 原手动桥接开关和既有 PK 计费、代理分配及重登预算。本次交付为独立 `Kilo` 分支源码，不发布版本标签、Release 或生产更新。

## 三个执行角色

| 角色 | 职责与保存的数据 |
| --- | --- |
| Sub2API Go 控制面 | 保存加密凭据、来源/网关配对、批次、任务、修订和租约；申请并独占消费设备 token，核验 Gateway Key，控制账号调度与请求出口。 |
| OpenAI quota OAuth worker | 复用现有 reauth 队列和发行绑定的运行包，按来源保存的账密/TOTP 获取官方身份与只读额度 OAuth。Kilo 额度任务使用支持固定代理的本地 Codex 协议；不会修改全局引擎。 |
| Kilo HTTP executor | 独立 service 1.1.0 / protocol 1；短期保存会话，执行登录、原身份恢复、订阅连接/观察/重新授权和设备批准。它不领取 quota OAuth 任务、不消费设备 token、不发模型请求。 |

现有 reauth manager 只监督 quota worker，不会自动启动 Kilo executor。执行器的构建、固定输入、权限、Compose/systemd 和实际验证边界见 [部署说明](../deploy/kilo-runtime/README.md)；协议说明见 [执行器 README](../tools/kilo-runtime/README.md)。

## 管理员接入

1. 使用完整管理员登录。准备 OpenAI 业务分组、启用且可用的代理，并通过现有凭据加密设置初始化持久加密密钥。密钥必须在更新和备份恢复中保留，不写入源码。
2. 进入 Kilo 工作台，或在添加 OpenAI 账号中选择「Kilo 2FA」。逐行输入原账号邮箱、密码及 TOTP，预览后为每份身份明确选择固定登录代理、个人/Business 工作区模式及可选 Kilo 组织。
3. 选择目标业务分组、全部可用请求代理或具名代理组，并设置请求出口数、每出口并发及账号并发。默认五个请求出口、各二十并发、账号一百并发；登录出口单独保留且不参加请求池。
4. 明确选择新建身份或优先可复用空槽。只有服务端已核验的独立身份可复用；同 GPT 登录创建的身份保留原始来源，不能自动换绑其他 GPT。
5. 提交后保留原 `request_id`。相同内容重提返回原批次，内容改变不能复用原请求身份。账密在浏览器仅驻留内存，服务端以加密配置保存，不进入审计请求体、任务 options 或日志。
6. 查看任务阶段：官方额度 OAuth、Kilo 身份、订阅授权、设备批准、Go 取得 Key、模型范围核验、请求代理分配和最终绑定。选择不立即激活时，完成接入仍保持网关停调。

也可导入已有 Kilo API Key，或通过设备授权取得 Key，再沿工作台的预备账号流程配置组织、来源和出口。只取得 Key 或看到已连接状态不等于已验证订阅可用。

## 双身份与推理边界

来源 GPT 从接入提交开始标记为 `kilo_quota_only`。该官方 OAuth 仅用于身份、正常授权和官方只读额度；取消、解绑、失败删除或释放请求代理均不能自动恢复官方推理。影子账号、透传、显式测试、糖果、插件、模型/额度探针和底层 HTTP 发送都遵守同一限制。

客户生成、管理测试和独立搜索仅通过已保存的 Kilo Key 与允许的 Kilo 网关发送。配对、凭据、端点、订阅模型证明或出口不满足时明确失败，不改用来源 OAuth，不向其他上游回退，也不因通用恢复策略换账号重放已发送的 Kilo 请求。Key 与持久双向配对的 GPT 来源以同一逻辑账号展示；详情/列表不返回原始凭据，Observer 不获得跨组来源身份。

模型范围由绑定 GPT 的新鲜模型目录、当前 Key/组织认证 BYOK 目录和通道兼容上限求交集，管理员选项只能收窄。证明绑定 Key 指纹、组织与来源身份；空映射、通配符、旧证明或目录错误不能放开全部模型。调度缓存保留同一证明，旧版本投影自动失效并由原调度链重建。

## 生命周期与恢复

- 固定登录代理保持原身份出口，不使用请求池代理、随机授权池或直连代替。请求出口按代理凭据指纹独占和计并发，公网 IP 只保存为历史信息。
- GPT 401 或明确工作区失效先走现有授权恢复、刷新和重登预算。拒绝信号绑定实际被拒令牌及恢复代次，旧请求不能覆盖已更新凭据。临时网络、配置阻断或关闭自动重登不冒充账号终态。
- Kilo 身份级 403 与 GPT 授权失败分开；供应方权限或边缘验证 403 不证明 Kilo 封禁。Kilo 失败通过凭据/配对 CAS 持久处理；旧 Key、旧绑定或保存失败不能再进入无版本比较的通用停调写入。
- 请求出口先停止新准入，等待在途响应和租约关闭后释放。取消先撤销任务修订，再关闭原远端 operation、ACK 和短期会话；未知结果保留原操作，不盲目重新授权。
- `gpt_coupled` 保留原 GPT 登录来源，原来源终态时本地退役；`independent` 须核验独立登录方式、保存会话且确认远端订阅断开才进入空闲池；`unknown` 不允许自由换绑。退役不等于上游封禁。
- 个人订阅出现原身份不一致或启用证据未知时，普通「重试任务」不能重新发授权。任务面板依据服务端资格显示「只读核对订阅」及需明确确认的「重新授权订阅」，携带 `expected_revision`；操作仍在后端锁内复核原身份、固定出口、材料、租约和远端会话闭合。

## 数据库与构建

只追加迁移 344–351，依序覆盖预备账号、出口租约、代理所有权、登录/请求分离、代理条目准入、来源接入、身份池和身份生命周期。446 份基线既有 SQL 保留原字节；复用 `263_account_proxy_bindings.sql`，不导入来源项目的集群表或部署体系。应用仍使用仓库现有迁移执行和权限流程，升级前按原规范备份；不将旧程序回退当作删除新表或重写迁移。

后端沿用现有 Go module、Wire 和构建入口；修改构造后运行 `go generate ./cmd/server`。前端使用既有包锁与构建，不加入其他工作台或品牌改动。Kilo 的工具搜索、结构化输出、显式载荷裁剪、Responses/Chat/Messages 适配和独立搜索继续使用现有账号、分组、计费及资金预占。

运行环境需配置同一专用 token：Go `KILO_EXECUTOR_URL` 与 `KILO_EXECUTOR_TOKEN_FILE`，执行器 `KILO_SERVICE_TOKEN_FILE`。明文 HTTP 只接受回环地址；容器示例通过共享应用网络命名空间使用 `http://127.0.0.1:8099`，不公开该端口。专用 GID/0640 token 与原应用降权入口的读取检查见部署说明。
