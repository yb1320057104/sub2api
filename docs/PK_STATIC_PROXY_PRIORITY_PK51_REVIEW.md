# 静态 IP 分组与严格账号优先级（pk.51）

基线为私库 main `a6f37609b51b4f788143ec1f1cacbcb6a4d5b83d`，正式上一版 `v0.2.19-pk.50`。新增 PK-045，扩展 PK-044，沿用 PK-021 管理员边界；本记录随实际实现、测试和发行更新。

## 用户场景与行为

10个静态代理分别设置全局并发10，3个账号共同绑定该池，账号优先级依次为1、2、3。业务分组开启顺序调度后先使用账号1；账号1健康但并发已满时不调用账号2/3，沿用现有等待或繁忙响应。账号1停调、限流、额度耗尽等不能调度时，在其已有请求全部结束后才允许账号2开始发送；账号总并发仍限制实际吞吐，10×10只是代理池的并发上限。当前模型或协议不兼容的账号也不参与该请求的选择。

IP分组是管理维度，业务分组是选择调度策略的维度。一个IP仅属于一个IP分组，同一IP池跨业务组仍共用容量和账号互斥。开关默认关闭。后台列表的按组配置操作明确替换账号原代理集合，保存前展示作用范围，服务端一次事务执行，失败不保留半份配置。

## 实现与兼容

IP分组的创建、改名、删除、归组和列表筛选只操作后台配置。业务分组可单行开关或勾选批量配置；账号列表复用一键分配入口，增加按IP分组模式。代理分组成员全部有效且不超过100个才允许分配；保留既有每IP账号上限，容量不足整体回滚，不静默扩大。只有母账号也在所选业务组内时才合并影子配置，避免隐性更改组外母账号。已启用严格策略引用的池不能直接增删/移动成员，数据库触发器也保护旧入口。

调度器从最新数据库配置选择 Priority 数值最小、同值ID最小的可调度账号，账号负载及本请求排除集合不构成调用备用账号的理由。普通粘性、模型路由和旧/新调度入口共同遵守选择；绑定原账号的响应续链不能跨账号重放。实际出站再次核对策略和选择，严格模式只选配置IP组内当前绑定的出口。

Redis原子租约按实际物理代理ID登记账号及原资源集合，不能通过不同业务组或部分重叠集合绕过互斥。普通模式仍允许账号并行，但一侧有严格请求时必须等待冲突账号的全部活动请求排空。每请求随机选定出口后保持固定，单IP及账号总并发限制继续叠加。Live既有租约继续续租直至结束；旧无托管租约的记录恢复需重新准入。租约失败或丢失拒绝继续出站，不复活失槽。

严格模式在选择和出站时读取最新策略与批量账号状态，优先保证管理员修改及健康状态一致性；没有把本机模拟当成生产吞吐压测。旧版本回退保留新表和已分配账号出口，但不具备新的严格优先级能力。
