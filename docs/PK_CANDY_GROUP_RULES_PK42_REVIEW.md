# v0.2.19-pk.42 分组糖果测试与授权开关

基线为私库 `main` / `v0.2.19-pk.41`，提交 `7a5f37b60f267356996dab368ce28d60ab9fb20c`。扩展 PK-019/021/034/035/036，无新增二开 ID。

## 用户确认与最终行为

- 账号观测的糖果测试按来源分组配置。每条规则选择一个来源分组、一个或多个合格目标分组、一个不合格目标分组；多条规则匹配同一账号时按设置顺序取第一条，只测试一次。
- 未配置来源规则的账号不自动测试，手动入口也会明确提示未配置，不发送模型请求。升级不会把历史全局目标转换为隐式全账号规则；管理员需添加来源规则。
- 全部启用模型均完整合格才替换原分组，加入全部所选合格目标。首个完整错答仍立即转到该规则的不合格目标，其余模型继续结束。技术错误、取消或不完整回复不新增转组，已经提交的不合格结果及转组证据保留。
- 授权工作台增加“授权后进行糖果测试”开关，可不输入账号而单独保存。关闭时不要求糖果模型或目标配置；新账号按所选入库分组经过原生准入后正常完成授权，已有账号保留分组、代理和人工停调状态。
- 开启授权测智后，已有账号按原分组、新账号按工作台入库分组匹配同一套规则。没有匹配规则则跳过测试；已有未分组账号不使用工作台入库组兜底。合格使用规则中的全部合格目标，不合格使用单个不合格目标。
- 新建工作台的开关默认为关闭；历史保存记录的开关值保留，但没有来源规则仍不测试。立即/定时授权读取已保存开关；已排队任务及失败重试保留其有效开关和模型快照，重试重新核对来源规则及当前有效目标。
- 用户澄清模型需求是补充下拉候选，不是取消最多 8 个模型限制。候选包含系统内置文本模型、当前 OpenAI 账号显式配置的模型名和已保存测试模型，去重排序并保留自定义 ID。候选不保证每个账号均支持；实际请求仍走该账号的模型映射与原出口。

- 立即/定时重授权产生的真实测智记录也同步雷达卡片、历史、最新判定与邮件筛选，来源保留手动/定时区分。

## 存储与接口

- 规则保存在 `settings.pk_radar_account_group_rules` JSON，和雷达配置 generation 在同一事务更新；来源、目标均校验有效 OpenAI 分组，合格目标不得为空或重复。保存要求显式 `group_rules` 数组，旧客户端不能覆盖新设置。
- 工作台复用 `settings.pk_authorization_workbench`，新增 `intelligence_gate` 返显和 `workbench_revision` 乐观锁；独立保存仅白名单持久化非敏感参数。巡检配置及其 revision 保持独立。
- 授权任务 JSON 保存有效开关、匹配来源和模型快照。规则被移除或来源停用时，等待后、发送前及运行期检查会停止新的测试；最终转组事务锁定当前规则和所有目标，复核原账号快照后原子更新。
- `PUT /admin/account-authorization/workbench` 独立保存工作台，仍为管理员接口；审计记录动作但省略请求正文，防止误传的账号内容进入日志。
- `GET /admin/radar/account-candy/models` 返回 `{models: string[]}`，仅读取本地模型配置；不调用上游、不返回账号凭据。非字符串映射、通配符和图像模型不作为糖果文本候选；加载失败可重试或继续手填模型 ID。
- 多分组合格转组使用雷达结果新增的完整目标列表保存实际去向；历史单目标字段保留兼容，不回填历史测试结果。迁移仅扩展雷达结果表，业务账号和账务历史不批量改写。

## 静态核对范围

| 范围 | 核对结论 |
| --- | --- |
| 来源范围 | 调度查询、claim 事务、执行前检查和列表状态均识别来源规则；未配置不会回退全账号 |
| 多组转移 | 所有目标先校验后整体提交，任一目标准入失败不产生部分绑定；原组快照及调度 outbox 保留 |
| 多模型判定 | 原 1～8 模型、并行与原生凭据/模型映射/代理链路保持；首错证据和全部及格条件保持 |
| 授权开关 | 手动提交、独立保存、立即/定时授权、旧任务重试、执行和最终分组调用链已核对 |
| 人工操作保护 | 账号身份、分组、凭据、人工停调、配置代次、租约与任务 owner 检查保持 |
| 后台运行 | 沿用原持久化 worker、启动门、并发及 3/10 分钟 cron，无新增独立调度器 |
| 其他二开 | 首字/计费、分组智商测试、账号健康统计、邮件、浏览器和 CF 配置保持；版本检测/回退来源随同轮仓库迁移切换，邮件读取真实定时授权测智结果 |
| 检查边界 | 功能初稿仅格式化和静态检查；后续必要构建、类型检查及制品验收见迁移报告，不执行真实账号/模型请求 |

本报告静态阶段结论不等于动态通过。用户后续要求迁移仓库及生产更新源，并明确当前没有 Jenkins，实际构建和部署按迁移报告单独记录，不挪用历史证据。
