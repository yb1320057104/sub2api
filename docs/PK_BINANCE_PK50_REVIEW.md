# pk.50 币安渠道主备代理

本轮扩展 PK-022/024/025/021。收款渠道可保存一条主专属代理和一条备用专属代理，两者分别加密且独立选择网关预探测。备用代理是可选项；未配置备用的旧渠道继续原单次查询、原超时和原轮询锁。备用模式要求存在主专属代理，防止主备交替变成隐式直连。

一次查询顺序固定为：主代理、立即备用、等待 5 秒后主代理、等待 10 秒后备用、等待 15 秒后主代理，总共最多 5 次尝试，其中最多 3 次退避。成功立即结束。DNS、连接拒绝/重置、网络超时及成功响应读取中断可切换；取消、代理认证/配置、TLS 证书校验、币安权限/IP 白名单、业务 HTTP 错误和 429/418 不自动切换。已知限流即使同时取消也保留跨接口冷却。

重试单位是完整只读查询，每次重新校时和签名，同一次查询及所有分页固定使用该出口。历史查询失败后丢弃部分收据，成功后才进入既有收据/订单/余额事务；本地入账失败不再请求币安。实时账单仍然只读，不结算余额。付款金额、倍率、订单归属、收据唯一身份和数据库入账幂等没有变化。

新增迁移 `262_binance_backup_proxy.sql`，仅添加备用密文、预探测开关及安全查询状态 JSON；旧迁移不修改。状态仅保存主/备、1～5 的次数、运行/等待/成功/失败及时间，客户端通过已有只读渠道列表刷新进度，不重复提交查账。保存留空保留、明确清除，查询进行中拒绝修改任何主备连接配置；实际修改备用配置沿用已知非限流错误的退避恢复，不解除真实限流。

启用备用时，历史查询预算 490 秒、持久租约 510 秒，覆盖五次各 90 秒的完整扫描和 30 秒退避及结算余量；实时账单预算 215 秒、租约 225 秒。前端仅币安专用查询接口延长超时，其他 API 保留原设置。未配置备用时服务预算仍为 100/40 秒、锁仍为 120/45 秒。应用 HTTP 服务原本不设置 WriteTimeout；外部反向代理的响应超时仍需覆盖所选查询预算，未擅自更改部署配置。

主备两个实际出口 IP 都应加入币安 API Key 白名单，地区和代理网关地址不代表出口 IP。本轮没有发出真实币安、模型或授权请求，没有改生产数据/容器，发布后由用户手动切换版本。
