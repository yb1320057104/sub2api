# 独立站点部署工具包 0.1.0

新建站点此前依赖具体服务器的人工配置和历史迁移脚本。现在提供 `deploy/cluster-kit/`：输入服务器、域名与模式后，一次命令安装单机或三机高可用站点，并生成独立数据库、Redis、管理员和密钥。

本次是私库部署工具及源码补丁包交付，不是新普通应用发行。使用 detached 隔离目录整理，未读取应用工作区未提交内容；不创建新 pk 应用标签、Release 或 GHCR 镜像，不触发已有站点网页更新。

| 保护项 | 结果与依据 |
| --- | --- |
| PK-047 | 新登记：Patroni/etcd、Redis/Sentinel、独立站点、后台职责、共享准入、固定源码及干净发布包。 |
| PK-017 / PK-021 | 保留私库来源及功能登记；包只包含白名单模板、固定基线补丁和说明，不含真实部署身份与业务数据。 |
| PK-016 | 新 HA 模板显式禁用普通网页自更新，防止替换为缺少 HA 能力的程序；普通应用发布流程未修改。 |

| 账务与其他既有功能 | 前端、全部324 SQL迁移、依赖锁文件和费用公式沿用固定基线；共享状态失败时按HA显式配置拒绝准入，不重放历史账务。 |

配置约束：首版支持 Ubuntu 24.04+ amd64 专用主机；单机一份数据，三机内两应用节点共享本站数据。站点之间凭据、存储与账号完全独立。异步复制保留可用性与丢失窗口，不承诺跨数据库/Redis原子性或全局恰好一次。主公网IP失效时使用副域名或另外配置DNS/LB，不能把节点内部转发当作公网地址接管。

源码取自固定 pk.58 提交 `fd80b8314fc2ddb9ec6470755abed0f741b27680`，通过合并后的 HA r4 补丁和逐文件SHA验证生成构建上下文。既有工作区和生产快照不进入包。新站本机构建镜像不等于发布官方应用二进制，正式应用发行仍走既有流程。

验证环境和实际结果详见 [部署包验证记录](../deploy/cluster-kit/VALIDATION.md)。本轮包含本地模板/状态机/配置负向检查和 Linux 隔离运行时配置检查、PostgreSQL/Redis初次初始化。未运行全套应用测试、未重建完整前后端发行镜像、未在三台全新宿主机完成端到端安装或断电验收。第一次容器DNS依赖下载失败已如实保留，随后离线依赖验证通过。

新增验证夹具仅保留在本机临时证据目录，未纳入提交或分享ZIP；应用原有测试保留在源码清单中。未变动既有生产数据库、账号、容器、域名或普通发行标签。

交付包括源码目录、`releases/sub2api-cluster-kit-0.1.0.zip`、`SHA256SUMS`；ZIP使用同一工具包源码白名单生成，排除生成站点目录、口令、私钥、用户数据和缓存。SHA验证后才上传私库。
