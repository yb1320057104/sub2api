# v0.2.19-pk.16 授权代理预检复核

## 需求与范围

用户反馈授权代理显示预检中并全部失败，要求对照其 wb-2fa 项目补齐指纹后测试。基线私库 main / v0.2.19-pk.15（51d856868059165d21796230e992acd853ea0055）；扩展 PK-036/021，无新增 ID。本次只做服务器匿名首页专项验证，不发送账号密码、2FA 或模型请求，不改业务数据，不升级/重启线上应用，不触发 Jenkins。

## 发现与修复

初次只读检查：100条已启用代理中，4条已有失败结果，96条尚未检查。导入只是加密保存；“预检中”来自正在等待手动检查请求的按钮，不是账号授权成功或后台已批量检测100条。

参考实现使用 curl_cffi 0.15.0 / Chrome 146，显式对齐 TLS 档位、UA、Client Hints 和导航头，默认最多3次新连接。原项目使用默认无头 Chromium 身份，且将网络/HTTP/验证页合并为同一错误，已确认失败仍继续最多45次等待，容易误认为卡住。

修复保留真实 Chromium 的 TLS 实现，从 Browser.getVersion 读取实际版本，统一设置 UA、Client Hints、语言和平台；不把已安装 Chromium 136 伪报为参考项目的146，不引入 Python 或 curl_cffi 运行依赖。预检与后续登录复用同一浏览器身份和强制代理链路。

新增主页网络错误、HTTP状态码和 cf-mitigated 验证页分类；单次明确失败立即结束。仅在提交账号凭据之前，对允许的预检失败最多重试3次新浏览器会话，保留同一代理、父 context 和总超时；不会重放登录、人工验证或 OAuth 回调，不直连兜底。仍然只允许正常2xx HTML且不是验证页的预检通过。没有HTTP响应时明确说明，不展示虚假的HTTP 0。

未检查代理单独显示“尚未预检”，导入提示明确手动 GET/授权前预检的触发方式。普通账号巡检的 unknown 文案不受影响。

## 实际验证（2026-10-31，Asia/Shanghai）

参考脚本在服务器一次性隔离容器执行，同两条线上失败代理均返回HTTP 200；未复制客户端会话或账号凭据。参考依赖、临时容器和测试文件执行后清理。

修改后的实际浏览器源文件在服务器独立容器编译为最小诊断入口，再以非root用户使用当前应用容器已安装的 Chromium 执行匿名预检；没有替换正在运行的应用。数据库查询仅用于读取已授权的代理，解密值仅在服务器进程内存和子进程stdin中传递，结果不包含代理密码或出口身份。
