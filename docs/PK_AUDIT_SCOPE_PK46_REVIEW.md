# pk.46 分组审计、本地规则与注册入口

## 范围与基线

从新私库 main `5bcdb1a029ac636967339fdc37ea33756c697fdc` / pk.45 继续，不合并上游。用户要求首页注册入口、内容审计与提示词审计按明确分组运行，以及无需节点的可编辑本地规则和包含违法色情的模板。本轮只发布 GitHub，由用户手动切换生产。

## 功能与保护核对

- PK-031：首页默认、简洁、自定义 HTML/iframe 布局，在未登录且开放注册时显示注册入口，保留登录/控制台和原注册校验。
- 新增 PK-041：两种审计分别只处理各自 group_ids；空列表、未选组、无分组跳过。旧 all_groups=true 不再全审，升级后需明确勾选需要审计的组。接口保留旧字段兼容但不再赋予全组效果。
- 提示词增加 local_rules 引擎：无需节点或节点 API Key，关键词和 Go RE2 正则对完整提取文本匹配，避免分片边界漏匹配。规则可编辑、启停、分类和选择 warn/block；异步只记录，开启同步阻止才实际拒绝 block 命中，warn放行。
- 默认模板七类：提示词注入、越权、密钥窃取默认block；违法操作、色情生成、暴力实施、自伤操作默认warn。说明模板可编辑/复制，但两种引擎均不执行这份自然语言说明。本地无法理解上下文，模板并非全面语义审核；保留远端Qwen3Guard模式及已有节点凭据。
- 64条规则、名称100字、匹配内容2000字、说明16000字；非法正则、可匹配空串、重复ID及未知枚举拒绝。明确删空规则不会重新加载默认模板，启用本地须至少一条启用规则；覆盖模板需前端确认。
- 提示词范围在请求复制、队列槽和故障阻断前独立判断；已排队任务扫描前重新确认分组。HTTP/WS去重绑定实际分组，Claude Code及prompt-too-long备用分组重审，避免原未选组掩盖已选备用组。
- 沿用PK-021管理权限与审计，不改原队列/事件结构、账务、首字计时、注册CF、更新token或加密密钥。配置使用现有JSON，无迁移、依赖或历史数据回填。规则正文不写入变更摘要；事件保留原完整提示词管理员访问边界。
- PK-001～028/032～040均静态核对为本轮无目标变更；PK-029/030仍为已移除项，不复用ID。未将本轮mock或历史验收称为真实上游功能实测。
