## 根因及修复范围

上游整合后的 `ProvideBackupService` 通过 `startBackgroundService` 启动服务；HA overlay 的 `BackupService.Start` 内部还调用 `startBackgroundAfterActivation`。外层启动门在持有互斥锁时调用 `Start`，内部再次取得同一非重入锁，造成 worker 初始化死锁。已启动的糖果等服务继续运行，后续渠道聚合、鹈鹕调度未构造；API 禁用共享后台，因此仍可正常接单和计费。

最小修复恢复 HA 备份服务自身掌管唯一启动门的合同。验证必须真实调用 provider，并以隔离同制品 worker 完成初始化和后台调度启动为验收条件；仅有进程 Running、API ready 或旧单元测试数量不能代替此项。

当前死锁发生在 main 注册信号处理和 drain probe 之前。旧 worker 不能声称支持完整优雅退出或伪造退出 0；恢复需先证明已启动任务与记账结清，保留两 API 可用和单 worker 边界，再按独立恢复方案处理正常 TERM 的真实退出结果。不得使用 SIGKILL、双 gate 停流或修改历史回执。
