# pk.68 下游 503 续修

## 起因与证据

pk.67 正式部署后，北京时间 2026-11-15 22:30:06–22:33:23 的约 3 分 17 秒窗口仍有 25 条独立请求 503：普通路由不可用 13、计费不可用 7、真实模型限流 5。另有 8 条上游流未完成 502。pk.67 的部署健康终验通过，不代表这些业务故障已经解决。

7 条计费失败均为余额读取 `cache_miss`，涉及两个正常且余额为正的用户，均无自动授信配置或过去 24 小时的授信审计。7/7 的同用户正额持久结算都在余额读取/补读窗口内完成缓存失效。源码显示每笔持久余额消费在标记缓存处理完成之前都会删除余额键；资格已读取余额后，并发结算可以删除该键，此时预约纯补读没有回填者。现场不记录每次 GET/DEL，不能声称每个请求内部的精确 Redis 顺序都已观测。

13 条普通路由 503 全部来自同一模型，日志均为唯一候选 `pool=1/runtime_blocked=1`；其中 2 条落在第二次失败触发的 10 秒冷却内，11 条落在第三次失败触发的 45 秒冷却内。该分组的其他账号分别为人工停调和真实额度限流，不能擅自启用或清除限制。

8 条上游 502 均保留了完整 132 字节错误体，其 SHA256 为 `c482996496f442dff85541433775d14f68841d47a4fc2332e3379d06a96dea98`。结构为顶层仅 `error`，内部仅 `code/message/type`，值为 `upstream_stream_incomplete`、`Upstream response stream ended before completion`、`upstream_error`。它们来自上游 HTTP 错误响应，非本地 200 SSE/WS 解析失败。对应日志窗口没有旧握手文本，因此不能把该窗口的新握手分类计数零解读为分类失效。

原始证据位于受限、忽略的 `.runtime/pk67-release/observations/` 下 `cache-miss-followup-01` 与 `routing-stream-audit-01`。不提交用户身份、请求标识、凭据或机器信息；不同窗口不直接计算改善率，usage 与错误事件也不直接相加计算请求失败率。

## 修改合同

1. 独立 pk68 HA profile 保留旧版本，在明确 Redis Nil 时，有界读取同一 writer DB 的当前用户与余额，并重新校验用户有效、余额有限及既有最低资格阈值。该路径不发布余额缓存快照、不调用异步回填或重新执行授信。真实 Redis 错误、数据库失败或取消继续拒绝；共享预约必须成功且只执行一次。
2. 保留原首请求正余额可超过估价的策略，以及固定费用自身更严格的资格规则。数据库读取和 Redis 预约仍非同一事务，不宣称本次消除了所有跨存储竞争。
3. 普通代码只对明确 OpenAI API Key 转发池、HTTP 502、严格结构化池内流未完成错误，抑制通用账号/模型短冷却。保留当前失败响应，不新增同号重试或输出后恢复许可。其他 5xx、真实限流、权限错误、管理员临时规则与显式重试配置继续生效。

## 验证与交付状态

普通侧四文件完成定向检查：Go 1.27.3 windows/amd64，33 个顶层测试、138 个包含子项的通过事件，零失败、零跳过。覆盖 Responses/Chat/Messages、透传与普通、流式与非流式的 12 种实际路由组合，显式重试配置、其他错误冷却、管理员规则，以及正文/工具/不透明历史的禁止重放保护。

独立 Go overlay 负对照只移除新的池内流未完成冷却条件，12/12 路由组合的第三个请求均从应有 200 复现为 503，进程按预期退出 1；共享工作区源码没有回退。原始证据在 `.runtime/pk68-stream-tests/`，`verification.json` SHA256 为 `c81e89d5427ae8223ada2383a97f32054b435f62b91ee8d51c6325913a5ce3ee`。这是隔离模拟上游测试，不能代替生产后验。

HA 回源与固定费用错误分支经过独立源码审阅：明确 Nil 才回源，继承取消和一秒上限，读取后再检查期限；不发布缓存或调用授信，单次预约和错误后同标识释放保留。固定费用将当前余额不足原样作为业务拒绝返回，不包装成 503。

初次冻结后的追加审阅发现上述审阅不充分：固定费用第一次余额足够后，若并发结算删除缓存，第二次回源余额仍为正但低于固定金额，原预约 Lua 在无其他在途记录时仍允许首请求。旧版本此处 Nil 会拒绝，新回源必须另外保留固定金额覆盖条件。已暂停新制品启动并追加仅固定费用的第二次金额检查，token 首请求策略不变；原冻结和已启动构建证据保留，不作为最终版本验收。新增回归使用余额 10→5、固定费用 8，避免只检查降为零而漏掉这个边界。

首次 HA 定向测试：服务 36 个顶层、76 个通过事件，仓储 13 个顶层、13 个通过事件，均无失败或跳过。旧 pk.67 读取函数负对照在新的“资格命中后被持久结算失效”用例真实返回 503，按预期失败；不是编译失败。该首次版本和证据保留，随后由下面固定费用边界修正取代。

最终 r2 服务定向测试为 37 个顶层、77 个通过事件，无失败或跳过。仅去掉固定费用二次金额保护时，新增 10→5/费用8 的用例真实失败；保留保护后固定费用拒绝且同余额的普通 token 首请求仍成功。profile 独立应用核对 96 个路径，93 个输出不变，仅余额读取、固定费用错误传递、既有 HA 测试三路径改变。最终补丁 SHA256 为 `31c29f730120c66e59fb82121cca3423d554bc80e2ae08fcac527f294eb7026b`，manifest SHA256 为 `dea406f0c5c3e18c70fc95854ead9ae6f50dc249663b89b493a08364e918a8e7`，本轮交接记录为 `.runtime/pk68-billing-test/fixed-charge-coverage/handoff.json`，SHA256 `99d800c425847e06cabfe98efbb0d44bc0387aff5dc26f639cd5e71f387c6164`。测试实际由 Go 1.27.3 自动工具链执行；首次报告误写模块目录外启动器版本 1.26.5，已在独立 amendment 保留原证据后更正，未为该元数据更正重复测试。
