## 上游安全策略最低扣款追加

用户追加要求上游安全策略实际成本为0也自动扣款。代码核对确认，旧“手动扣除余额倍率” `cyber_policy_settings.multiplier` 实为每次固定金额，手扣公式为次数×该值；自动函数仅做实际成本×分组破甲倍率，没有使用它，因此界面出现“计算额为0，未扣费”。

本轮复用已保存值，界面明确为“上游安全策略每次最低扣款（USD）”。新type4自动金额为 `ROUND(max(actual_cost×分组破甲倍率,每次最低额),8)`。默认值仍为6.7，已保存值优先；没有另造一套金额设置。内容/提示词前置拦截的0成本与观察记录仍不产生此保底。分组选中、自动扣费开关、用户豁免、余额充足、去重及失败回滚保持；已扣、零额或失败历史一律不追扣。

例如每次最低额为6.7，实际模型成本为0：上游成功扣6.7后生成实扣回执；同款下游关联自己的原用量，只扣触发请求的本地用户6.7，其他用户不扣，不再额外加下游最低额。远端用户ID与本地ID不相互映射。原生下游只收到正常标准响应，追加额留在上游本站结算。

新增迁移267保存最低额/公式/来源快照及内部远端事件标记。标记只接受账号显式开启、服务端真实发出的协商和合法回执；原usage插入前持久化，本站相同type4不再重复自动计数/最低额/手动扣款，使用记录及导入流水保留。缺少标记的旧用量不能事后贴回执补扣。最低额改动也纳入配置修订号。

追加验证已完成：最低额、上游安全拒绝的 HTTP/SSE 传递及下游原请求用户扣款见下方最终验收；以前的零额记录仍反映当时规则，不回写为新最低额。

## 设置与操作

统一入口 `/admin/audit-center` 按范围与豁免、检测引擎、风险处理与分组处罚、执行记录组织。关键词属于内容审计引擎。旧入口保持路由兼容，原配置、密钥、规则和历史仍是权威存储；打开页面不保存、不加载模板替换旧规则。

三套范围、豁免或风险策略不一致时展示来源，需要显式采用共享值才同步。总开关、引擎专属字段与共享字段在一次事务中保存，修订冲突或任一存储错误全部回滚。内容旧版独立封禁状态必须可见且可明确管理，不因整合而静默关闭。

要让本地命中产生追加费用，应选择需要审计的组，启用对应引擎并采用同步/前置执行，将所需风险档设置为“扣费放行”，在同组开启自动扣费并设置破甲倍率；请求须正常完成、有正的实际成本、用户不在相关豁免名单且余额足够。关键词未命中后的异步API结果仅观察，不能处罚。本地立即拦截没有上游费用，不套用上游type4最低额；上游type4最低额单独作为处罚流水，不虚构模型成本。是否降低80分门槛由管理员根据规则实际评分决定，本轮不擅自修改生产阈值。

诊断展示当前分组可执行状态及近24小时扣款原因，包含观察、零成本、豁免、未选组、扣费关闭、余额不足及执行失败。汇总最多读取最近10000条并明确标注取样上限，不能将其冒称无限制全量统计。

## 同款下游结算合同

- 下游管理员显式开启对应账号 `extra.audit_settlement_enabled`，默认关闭。支持 OpenAI/Anthropic 的 API Key 或 upstream 账号，配置根地址或 `/v1` 及 API Key。只对实际发出的 HTTP Responses、Chat Completions、Messages 请求协商，含SSE；WS、Live、异步媒体任务不协商本合同。
- 请求头 `X-Sub2api-Audit-Settlement: v1`；支持的上游生成本地独立 UUID 回执并返回同名能力头和 `X-Sub2api-Audit-Receipt`。上游透传头不能覆盖本地回执。
- 使用同一上游 API Key 查询 `GET /v1/sub2api/audit-settlements/:id`。只有归属用户和Key匹配才返回；保留Key真实性/禁用状态和IP ACL，允许刚被扣空余额或自动禁用的用户读取该Key已产生的回执，绝不扩大模型调用权限。提供端未完成回执超过24小时标为不可用。
- 回执区分 `pending/ready/unavailable`。只有 `ready` 含USD实际已扣追加金额和稳定明细ID；不传倍率、不传提示词、不伪造token。原生未协商时正常执行原接口，本站追加费用不传递给它。
- 下游先持久关联本地真实用量，再后台认证查询并结算。请求上下文的服务端协商标记防止仅凭上游自报字段进入扣费；关联使用上游地址/Key指纹、账号、用户、Key和用量身份。实际发出的认证头须匹配账号API Key才协商；变更凭据或关闭接收时不盲用新身份补扣。
- 同一原用量只可导出一次，同一上游身份与回执组合只可导入一次。多跳必须等待导入结算终态，金额只累加本地及导入的实际扣款，不再次乘倍率。金额使用8位定点十进制、校验逐项之和，接收端单回执上限100万美元、最多128项，超限拒绝结算并记录不可用；提供端不截断其实际扣款金额。
- 追加费用是独立余额流水，不改原用量费用/token、订阅用量或API Key额度，也不再计为本地审计违规或再次触发破甲倍率。并发扣款锁定用户和结算身份；余额、负额余额流水及缓存失效证据同事务提交。余额不足不负扣、不追补，技术失败保留终态证据。开始金额事务前先耐久写入 `charge_started_at`；崩溃留下的执行中记录仅转失败，不重新发起扣款。
- 查询沿用配置的出站校验及账号多代理租约，禁止重定向和失败直连；属于账号级账单查询，不伪造模型分组调度门。最多4个查询并发，满批继续处理，单请求8秒，网络/pending有限重试；最多100次或23小时后明确不可用，金融终态不重试。
- 新迁移265/266增加回执和导入结算表及结算函数，267增加最低额及远端type4事件标记；旧迁移/历史保持。回执查询有效期30天；未实现历史追加费用重算或补扣。
