# v0.2.19-pk.33 重授权恢复与测智等待

日期：2026-10-31。基线：私库 main / v0.2.19-pk.32，`9e0a539f39a319984c2205f3ea05f6cae83c9810`。沿用 PK-031/034/035/036/021，无新增 ID、数据库表或迁移。

## 依据与原因

用户要求授权保存后等待一分钟再测智，并恢复账号错误自动关闭的调度。代码显示 OAuth code 交换本来同步完成；事务提交完整 access/refresh token 后，测智重新读取账号并直接取账号对象的 access token。截图中的通用请求失败不能证明旧 token 或交换尚未完成，未执行真实请求归因验证。

确认的调度缺口是：重授权先清除系统错误并开启调度，随后统一测智关卡再次将账号清组、停调；模型请求失败时流程提前结束，无法进入最后的调度恢复。

另查到缓存代次缺口：重授权原来沿用旧 `_token_version`，已持有旧账号对象的请求可能在删除缓存后重新写入旧 token。此次重授权在持有账号行锁时单调推进该字段，复用原生 `CheckTokenVersion` 对过时代次的保护；不把这一代码竞态直接当作截图请求失败的实测结论。

此次没有改造上游所有 OAuth 刷新的持久化协议，也不宣称解决所有在途刷新竞态。等待或测试期间若凭据再次变化，任务快照校验拒绝继续转组，保留当前账号状态。

## 本次行为

- 授权凭据保存后等待至少 60 秒；当前任务显示剩余秒数，每五秒复核所有权/取消/配置，进程停止或超时取消等待。普通糖果测试、雷达测智及既有 3/10 分钟 cron 不增加新的调度器。
- 已有账号保留原分组。只有系统 error 状态执行原生清错和开启调度，人工 inactive、active 且人工停调均保留。运行时阻断通过事务成功后的原生钩子清除，调度 outbox 与提交后快照刷新保持。
- 测智请求失败、不完整响应、取消/中断不回滚成功授权，不重新关闭已有账号调度，不将请求失败当作答错。已有分组写入任务元数据，成功分组后再更新。
- 新账号依旧无组、停调，完整测智及准入通过才分组并开调度。及格使用任务所选多组，不及格在转组事务内读取当前糖果不合格组。
- 凭据提交事务内捕获账号身份、状态、调度与组集合；一分钟后、每模型开始前、最终分组事务重新查询并校验。期间人工改凭据、代理、组或开关，不会被此次任务覆盖。
- 缓存失效在提交后与等待后执行；失败明确显示缓存待刷新，不发送该轮模型请求。原 cron 继续重试缓存，状态标记绑定当前凭据版本，旧结果不标记新凭据已刷新。
- 原缓存失效实现遇删除失败只记录日志并返回成功。本次为授权流程提供严格失效入口，返回实际删除错误；其它既有调用仍保持原有尽力清理语义，未扩大到其它平台业务。
- 账号授权菜单换为共享图标组件已有的认证徽章，无新依赖。中英文等待阶段、流程和失败/中断说明同步。
