## Messages 转 Chat Completions 的速度策略

此前该路径以“转换后没有 service_tier”为由跳过 Fast 策略，导致 `missing→force_ultrafast` 无法生效。现在在转换后调用现有共享策略；强制、过滤、拒绝和作用范围沿用共同实现，拒绝发生在请求上游前并保留本地策略拒绝分类。

供计费使用的请求档位从策略处理后的实际出站正文提取；上游回显优先和降档计费保持现有处理，不引入新定价公式。省略且无匹配规则仍不自动添加档位。原 BetaFast 头转译、协议路由和首字计时不扩改。

## 续传恢复的重复推理映射

Kilo API Key 的 gpt-6-astra 可使用续传。此前第一次 `ultra→high` 后若上游返回 previous_response_not_found/unsupported，恢复递归使用改写后的正文，可能继续命中 `high→deny` 并把原先允许的请求拒绝。

现在在入口保留原始正文，续传缓存失效后从原始请求重新执行一次策略。任务恢复分支同样使用原始正文；Grok 签名恢复仅在原始正文上剥离原有指定签名。服务端续传缓存清理、恢复标记、重试条件和计时位置保持。原始请求档位、消息/工具历史和客户/账号费用合同不改变，初次拒绝仍不得发出上游请求。
