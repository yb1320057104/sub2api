# Sub2API pk.63：种菜导入与按 IP 分组兼容升级

正式版本：[v0.2.19-pk.63](https://github.com/yb1320057104/sub2api/releases/tag/v0.2.19-pk.63)

本版本修复受限管理密钥的种菜导入与结果核对，并增加受限密钥的 IP 分组读取、分配权限。完整管理密钥和受限管理密钥此前使用的接口权限不同，因此会出现管理员可用、其他连接报错或缺少选项的情况。代码没有按种菜用户编号特殊放行。

## 配置现有受限密钥

在接收站的受限管理密钥设置中，将账号规则限定为需要导入的目标业务分组、`openai` 平台和 `oauth` 类型，授予以下权限。已有密钥不会自动增加权限。

| 范围 | 权限 | 用途 |
| --- | --- | --- |
| 目标组的账号规则 | `accounts.read` | 脱敏读取、原操作回执及结果核对 |
| 同一账号规则 | `accounts.create` | 创建账号 |
| 同一账号规则 | `accounts.credentials` | 写入凭证，不包含读取凭证 |
| 同一账号规则 | `accounts.schedule` | 设置并发、优先级及有效期 |
| 同一账号规则 | `accounts.network` | 设置代理或显式直连 |
| 目标业务分组规则 | `groups.models.read` | 读取限定分组的选择列表 |
| 全局权限 | `proxies.read` | 读取代理候选，不含认证凭证 |
| 全局权限，使用 IP 分组时需要 | `proxy-groups.read` | 读取 IP 分组及成员 |
| 全局权限，使用 IP 分组时需要 | `proxy-groups.assign` | 将 IP 分组分配给授权账号 |

已经明确授予全局 `groups.read` 的密钥也可读取分组列表；它比目标分组的 `groups.models.read` 范围更宽，两者不必同时授予。若允许无业务分组导入，还须明确允许未分组账号。

IP 分组分配权限会修改共享 IP 的全局并发，并将绑定账号上限设为不限；这可能影响已经使用这些 IP 的其他账号。站点管理员应按实际管理范围决定是否授予。账号级读取、网络和调度限制仍会逐个校验。

## 在种菜重新读取连接

接收站升级、权限保存后，重新校验原有 Sub2API 连接并刷新连接选项。成功读取 IP 分组列表只说明具有读取权限；执行分配还需要 `proxy-groups.assign`。

新接口协商协议为 `zhongcai-import-v1`，通过持久操作回执核对结果并防止同一操作重复创建。版本、权限或参数等确定性错误会显示具体原因并停止无效自动重试。

历史任务如显示原结果未知，应先核对并继续原操作，避免更换操作 ID 或反复新建导入。仅更新种菜端不会使旧接收站自动获得新接口；客户自建接收站须由其管理员安装升级。
