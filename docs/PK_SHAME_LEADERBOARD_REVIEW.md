## 实现与数据边界

- `/security-policy-ranking` 独立前端路由，普通用户请求同名只读 API；管理员调用 `/admin/security-policy-ranking`。管理员 API 经过管理员路由中间件及处理器角色检查；普通用户 DTO 不包含邮箱、余额、用户ID、倍率或扣费信息。
- 按 `usage_logs.request_type=4` 聚合；日期含起止日，SQL 使用指定时区的左闭右开区间，正确处理夏令时。默认今天，排序按触发次数降序、用户ID稳定排序，使用数据库分页。
- 管理员修改倍率只影响新的扣费预览。预览冻结记录集合、时间、操作者及倍率，10分钟有效；确认使用同一预览ID，重复请求返回原已完成结果。跨管理员、跨日期范围依赖逐记录唯一约束避免重复扣款。
- 一笔事务更新余额、负值 `admin_balance` 余额流水、已完成批次及记录认领；余额不足全部回滚。原模型费用和充值总额不变。实际金额使用数据库 decimal 运算，服务端响应保留精确十进制字符串。
- `244_security_policy_ranking.sql` 新建配置、预览、扣费明细及索引；`245_cyber_policy_auto_disable.sql` 新建独立计数与触发器。迁移不自动扣款、不回算历史触发次数，自动禁用默认关闭。
- 自动禁用只累计规则开启期间新入库的安全策略记录，管理员豁免。按用户行锁串行化并发累计，批量写入按用户ID顺序取锁；使用 `FOR NO KEY UPDATE` 避免与使用记录外键检查的 `KEY SHARE` 锁升级冲突。
- 达阈值事务内禁用，复用既有鉴权失效 outbox；没有新增后台服务。手动禁用→启用由用户表触发器按配置重计，使用记录清理不删除自动禁用计数或扣费凭据。
- 使用记录异步入库与鉴权广播存在延迟，禁用不强制终止已经开始的请求。排行只统计仍保存的使用记录；程序回退不撤销余额变化、禁用状态或数据库触发器。旧版没有规则配置入口，回退前应在新版核对并关闭自动禁用。
