# 雷达邮件提醒 — v0.2.19-pk.38

基线：私库 main / v0.2.19-pk.37，`d2cac661a5b2cdb94cab55f1611281c20bf4093a`。新增 PK-038，扩展 PK-035 的管理员入口，沿用 PK-019 启动门及 PK-021 交接规则。

## 用户要求与配置

- 雷达观测站新增“邮件配置”。收件人由本页配置，发件信息复用系统设置中的 SMTP；不复制密码或添加另一套发件配置。
- 默认禁用，检查周期30分钟，最低数量1，三个筛选条件默认全选；支持1至10080分钟、阈值1至1000000、最多20个收件邮箱。至少选择一个条件，选中条件同时满足。
- 三个条件分别为额度**使用率低于100%**、测智合格、不是401账号。匹配数量严格小于阈值才提醒，等于阈值不发。持续不足时按设置周期继续提醒。
- 页面显示最近检查时间、匹配数/总数、未知额度数量、下一次时间、最近发送时间和发送结果；查询或发信失败明确显示，不伪造检查成功。

## 统计与发送边界

- 每轮重新读取账号管理中当前未删除账号，不缓存账号名单，不修改账号凭据、代理、分组或调度。
- 额度来自OpenAI OAuth账号自身已有的5小时/7天原生持久化快照，遵循现有窗口重置语义，所有已知窗口均低于100%才满足；缺失或不支持的额度不冒充可用，也不为邮件任务发起外部额度探测。未知额度数只在启用额度条件时统计。
- 合格状态复用雷达最新有效测智判定，包括符合规则的授权准入结果；未知、过时代次和未完成判定不能当合格。
- 401只看当前账号错误及仍生效的临时401状态，不按历史使用日志排除已恢复账号。
- 邮件仅包含聚合数量、阈值、条件和检查时间，不包含账号密码、2FA、token或代理凭证。收件邮箱校验、去重，HTML动态内容转义，SMTP错误只对外给出安全说明。

## 调度与存储

- 服务端每分钟cron检查持久化的下一次时间；前端刷新仅展示状态，不执行统计和发信。启用或保存设置后等待下一个分钟cron。
- 独立配置与最近结果表，默认关闭；配置修订冲突返回409防止旧页面覆盖新设置，保存新配置后清空旧条件下的统计与本轮计数，保留最近真实发送时间；旧轮次不能覆盖新结果。
- 跨实例数据库锁与进程内互斥避免并行重复执行；先推进本周期时间，失败等待下一周期，重启不补发所有错过的提醒。
- SMTP配置先从系统设置读取，统计事务复用持有会话锁的同一连接，避免单连接池自等待。统计最多45秒，整轮最多20分钟；SMTP沿用现有拨号/会话截止时间，收件人逐个发送，不将数据库事务跨越网络发信。
- 发信前复查配置仍启用且修订一致；停服取消后不开始新的收件人发送。SMTP已提交的邮件不能撤回，进程故障临界点不承诺严格exactly-once投递。
- GET/PUT接口仅完整权限管理员可用，复用审计与no-store响应，不公开SMTP凭据。

## 验证及交接

本轮只进行源码、SQL、权限、接口类型、中英文案、生命周期、格式与差异静态核对。未运行本地/服务器构建、测试或typecheck，未调用模型/账号接口，未发送真实邮件，未连接或修改线上、触发Jenkins或部署。不把静态核对描述为运行通过。

静态审查已发现并修正配置CAS响应码不一致、新配置混用旧统计结果、单连接池持锁后二次借连接及邮件等待延误原糖果任务取消的问题。停止时先取消糖果任务，邮件准入锁不跨越SMTP网络调用；已开始发送由原SMTP截止时间收尾。下面为源码分支核对，**不是动态执行结果**：

| 场景 | 源码行为 |
|---|---|
| 匹配数等于阈值 | healthy，不发送 |
| 无账号且阈值至少1 | 匹配0，发送不足提醒 |
| 未选合格/额度条件 | 不按该条件限制；无需测智join/额度extra |
| 查询失败或未知数量 | check_failed，不按0发信 |
| SMTP不可用/部分失败 | send_failed/partial，展示安全说明，按周期再检查 |
| 两实例同一时刻cron | 会话advisory锁只能有一个持有者 |
| 管理员修改或关闭配置 | revision和run token阻止后续发送与旧结果覆盖；已开始SMTP不可撤回 |
| 执行中重启 | 中断状态保留证据，等待下一周期，不重放本轮 |
| 使用受限账号管理key | 后端拒绝，不返回收件配置 |
