# 分组防蒸馏用户白名单

目标版本 `v0.2.19-pk.60`，基于私库 `main` 的 `dcbf50a2ae0eeec30661b2fcfe0bbab17f6233ba`。本次响应用户要求：比较 `ranxi2001/sub2api`，并在分组管理的“OpenAI 防蒸馏保护（零缓存规则）”中增加可搜索、选择用户的白名单。比较不代表合并上游，源码交付不代表生产部署。

## 行为与兼容

- 每个 OpenAI 分组独立保存 `user_allowlist_ids`。管理员可以按邮箱、用户名或用户 ID 搜索，添加、移除或清空用户，与保护开关、暂停分钟数一起独立保存。
- 白名单用户在本组跳过零缓存暂停检查和样本记录，包括此前在其他组已触发共享暂停的用户；不清除用户的共享窗口或暂停，其他未豁免且开启保护的分组仍按原规则处理。移除豁免后，尚未到期的共享暂停仍有效。
- 不豁免用户禁用、API Key 权限、余额/订阅/额度、其他内容/提示词审计或正常计费；不变更上游账号状态，不自动切组，也不修改已开始的响应。
- 旧配置缺少名单时默认空；旧客户端 PUT 省略新字段时保留持久名单，显式 `[]` 清空，`null` 拒绝。省略名单的保存按 settings 原始值进行数据库比较交换，避免旧客户端覆盖另一节点刚更新或清空的名单；竞争最多重试3次，仍竞争则409并保留现有配置。列表最多 500 项，去重排序，验证正整数及用户仍存在且未删除；无效用户报错标出问题ID，保存失败保留原配置。
- 名单复用 settings JSON，不增加迁移或依赖。请求路径只在原分组配置缓存中判断用户 ID，不逐请求查询用户表；缓存保持最多 512 组及 10 秒 TTL，多节点变更遵循原短缓存时效。名单数组在缓存和返回值之间隔离。
- 前端复用既有用户白名单选择器，防蒸馏场景采用搜索防抖、过期结果隔离、最多 500 人和有限详情补全；名单中的旧 ID 保留可移除。既有审计选择器的默认配置保持。
- 接口仍为 `GET/PUT /api/v1/admin/groups/:id/anti-distillation`，写入仍仅完整管理员，简易模式和只读委派边界保持。用户搜索复用既有管理员接口，不向普通用户增加名单接口。
- HA需要全部应用节点升级到支持新字段的版本后再配置名单；兼容旧客户端不代表旧服务端能保存它不认识的新字段。各节点均升级后，名单变更沿用最多10秒配置缓存时效。

功能比较见 [固定快照比较报告](PK_RANXI_COMPARISON_PK60.md)，涵盖15个功能域，不把已移植保护或已有糖果/代理/支付基础能力重复列作缺失。
