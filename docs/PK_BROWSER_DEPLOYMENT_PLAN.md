# 浏览器随完整部署包交付（v0.2.19-pk.10）

基线私库main / v0.2.19-pk.9：3393cbbcd86d1400f50150f8a3595203e3eef0e2。沿用PK-017/020/021/036。

## 需求和现场

用户要求Chromium及运行库直接带进部署包，不让新部署者额外安装或配置。只读检查确认当前应用仍使用pk.5底座镜像，浏览器和默认环境变量缺失，原固定加密密钥已配置；未输出、替换密钥或修改线上服务。用户随后明确自己在Jenkins打新版本包，当前缺失在换用完整包里的应用镜像后解决。

## 实现

- 原Docker镜像已经内置Chromium和容器默认参数。新增完整部署资产，原样封入同次已构建应用镜像，不增加第二次编译或浏览器下载环节。
- 完整包含镜像、受保护Compose模板、image/image-id、SHA256SUMS、安装入口和说明。新目录初始化自动生成固定加密密钥等秘密，写0600的.env；项目名随机隔离、默认仅回环监听。不在包内预置任何用户/代理凭据。
- Docker和Compose是原有部署前提。数据库/Redis标准镜像在首次启动自动拉取；无需主机安装Chromium、浏览器运行库或设置路径。已有部署只load-only导入镜像，再保留原项目/数据/密钥按维护流程更新应用容器，拒绝直接初始化非空目录。
- 旧网页更新器按linux_amd64子串选择资产，因此新资产名使用sub2api-deployment-版本-amd64.tgz；原单二进制包和checksum行保留。不能声称网页换二进制会更新旧镜像底座。
- inventory/seal/restore/ready/publish绑定完整包及逐项摘要，内嵌镜像字节必须和原封存镜像完全相同；原十一项保持，新增browser-runtime检查无网络、非root本地页面渲染及临时目录清理。新版本不允许去掉部署profile冒充旧包；旧封存规则不降低。
