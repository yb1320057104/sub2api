# PK-044 账号多代理及容量分配（pk.50）

本次只发布私库 GitHub Release，用户手动切换生产。业务流量、授权和币安接口不参与模拟验证；下述实现与实际验证结果分别记录。

## 后端契约

- 账号 `proxy_bindings` 返回有序代理集合及每代理全局 `max_concurrency`、`max_accounts`、`current_concurrency`。并发读取失败显示未知（null）；两个限额为 0 时沿用不限。新集合输出不包含代理认证用户名或密码。
- 账号编辑及批量编辑可提交 `proxy_bindings: [{proxy_id,max_concurrency,max_accounts}]`。省略不改，空数组明确清空为直连；列表最多 100 个，代理编号不能重复，两个限额为 0～10000。限额修改对使用同一代理的所有账号生效。
- 一键接口 `POST /admin/accounts/assign-proxies` 接收账号 ID、每账号代理数、每代理最大账号数及每代理并发。最多 5000 个账号，每账号 1～100 代理；两个限额为 1～10000。只允许完整管理员。整体容量不足时事务回滚，不保留半份分配。
- 分配首先保留完整有效的既有方案，使重复提交稳定；需要重新规划时按剩余容量分配不同代理，避免保留局部旧分配导致可行池被错误判断不足。所有账号修改与代理配置在同一事务提交。

## 兼容与数据库

兼容迁移 `263_account_proxy_bindings.sql` 新增关联、全局容量和到期回退快照表，以及有效关联视图。无多代理配置时读取原 `accounts.proxy_id`，不回填历史账号。首个代理同步为 legacy primary，供已有后台任务和旧程序使用。

Spark 影子账号从母账号继承完整代理集合，不能独立修改；容量按原账号计数，影子不重复占名额。代理列表数量、删除保护、授权入库、最空闲选择、雷达备用空闲检查均使用完整关联。代理编辑会更新关联账号的调度快照。

事务级分配锁及数据库触发器使旧导入/编辑路径也遵守持久化账号上限；恢复软删除账号时检查整个原集合。旧接口明确修改 primary 时清除旧多代理配置，避免出现相互矛盾的路由。

到期只执行用户配置的 fallback：备用代理必须可用且有容量；容量不足保留失败出口供运行时选择其它成员或拒绝。明确直连回退删除该成员，仍有其它代理时继续使用集合，仅最后成员也被明确移除才直连。首次回退保存原完整集合，手动恢复重新验证原代理状态和容量，不覆盖代理当前全局限额。配置页主动修改会清除旧回退快照。回退应用版本保留数据和 primary，不回灌数据库。

## 运行时与验证

运行时随机选择及 Redis 租约由同版 `AccountProxyRouter` 接入 HTTP、WS 和 Live；一次请求/流固定出口，代理满额或无效不会隐式直连，账号总并发继续生效。

运行时独立审查追加：未命中 OpenAI OAuth 插件的请求跳过插件入口的代理准入，避免正常 HTTP 路径重复读取绑定和申请槽位。Anthropic 自定义 relay 由服务内部 context 明确标记，HTTP 层把实际选中出口写入 `proxy` 查询参数，连接 relay 本身仍按原语义直连，且使用同一份租约；普通 URL 查询参数不能启用该模式，后台明确选择代理的请求继续保留原值。

Live 通话在创建前申请一次代理租约，HTTP/plugin 仅借用，读完/关闭创建响应不释放。保存成功后停止创建阶段 keeper，不释放 Redis 槽，由持久化的 `ProxyID`、`ProxyLeaseID`、`ProxyLeaseManaged` 及既有 observer/controller 生命周期续租与最终释放；接管与重连不再次申请槽位，网络重连等待期间也续租。旧记录首次接管通过 Redis 条件写入升级，保留控制权字段，竞争输家释放临时槽；容量 1 的竞争者会读取赢家的持久租约。丢失的租约不能复活，解绑后的固定出口不能变为直连；活动控制循环发现租约失效会尝试发送 `session.close` 并终止本地转发。创建/保存失败释放未转移槽，进程崩溃或无人续接最多 60 秒自动过期。尚未完成整场链路的外部真实 Live 请求验收，验证使用本机模拟和 Redis 夹具。

## 前端设置与状态

账号编辑和批量编辑共用独立代理池卡片，可搜索添加不同代理、移除单条/全部，并逐条设置全局并发及账号上限。新选代理继承接口返回的现有限额，0 明确显示为不限；提示修改影响所有绑定账号。进入编辑/批改时刷新代理数量与全局限额，查询失败清除可选项，避免拿旧选项覆盖当前配置。账号编辑只有修改代理时才提交 `proxy_bindings`，无关字段修改省略代理字段；空集合明确直连，不同时发送 legacy `proxy_id`。影子账号的单独编辑不出现代理编辑器。

账号原来默认可见的容量列和可选代理列均逐条显示代理名称及当前总并发/上限，未知实时值显示 `—`，真实空闲显示 0，不限显示 `∞`，满额提示为红色。影子账号标为继承。代理列保留每条代理到期信息及原回退恢复入口；列表自动刷新会比较代理集合实时值。

勾选账号后可点击“一键分配代理”，独立弹窗冻结本次选择并填写每账号代理数、每代理最多账号数、每代理并发。默认 1/1/3，显示目标绑定数量与容量不足整批不修改说明；提交期间防重复操作，错误保留表单供调整。成功后刷新账号列表。普通新账号创建继续兼容既有单代理入口；账号授权工作台的多代理适配见下文。

## 账号授权出口

授权工作台的账号出口另支持 `proxies_per_account`（1～100）、`proxy_concurrency`（1～10000）及 `max_accounts_per_proxy`（扩大为与账号分配一致的 1～10000）。新前端默认值依次为 1、3、3。只在新账号选择 IP 管理出口时生效；登录用的授权代理池仍然独立，未替换浏览器登录代理。

新账号从有效且未到期的 IP 管理池选择不同代理，优先当前账号数较少者。两个全局限额都取提交值与已有非零限额的较小值；授权入库只能收紧已有全局限制，需提高时使用账号编辑或一键分配。降低限额影响该代理所有账号。容量不足不保留部分分配，账号创建、全局限额和完整绑定调用 PK-044 仓储，使用同一事务提交或回滚。

既有工作台 JSON 和排队任务没有 `proxy_concurrency` 时保留旧版单代理选择及原全局并发；不会自动套用界面默认 3。GET 配置给新前端显示默认值，用户显式保存或提交后才进入新配置。已有账号重授权重新读取最新账号，仅更新凭据；任务表单中的代理模式、数量与限额均不覆盖它当前的完整代理集合，包括排队期间已手动调整的集合。

配置和任务继续使用现有 JSON，无新增迁移。任务完成记录 `account_proxy_ids`、`account_proxy_bindings`（只有 ID 与实际生效两个限额）及 `account_proxy_preserved`，列表显式返回这些安全字段，让结果展示真实限额而非原始期望值。专项单测覆盖 JSON 默认/快照、容量与限额取小、同事务绑定及失败回滚、重授权保留最新绑定和结果快照；真实授权与模型请求未执行。最终验证结果以授权专项日志为准。
