# pk.63 受限管理密钥导入与 IP 分组兼容

## 原因和范围

种菜使用受限管理密钥时，旧通用账号接口拒绝 OAuth 身份、整数到期时间及导入关联字段；返回的脱敏账号也不包含原核对流程需要的身份标识。该创建路径没有永久操作回执。完整管理密钥不经过这条受限字段路径，因此表现不同。旧受限权限目录同时缺少 IP 分组列表和分配授权。

本版新增 PK-077，扩展 PK-014/044/045，沿用 PK-017/020/021/047 的可信发行约束。没有按种菜用户编号判断的特例；不将受限密钥替换为完整管理密钥，不自动给已有密钥增加权限。未合并新的上游源码。

## 接口与数据

受限管理密钥先通过 `GET /api/v1/admin/accounts/import/zhongcai` 协商 `zhongcai-import-v1`。POST 仅接受约定的 OpenAI OAuth 字段，原始请求字节的 SHA256 绑定完整载荷；重复字段、未知字段、大小超限及无效类型均拒绝。`proxy_id: null` 仍是显式网络配置，需要对应网络权限。完整管理员继续使用既有接口。

迁移 `340_zhongcai_import_receipts.sql` 仅新增操作回执表。稳定 KeyID、来源 UUID、操作 UUID 构成永久唯一键；账号、业务分组和回执在同一事务提交。相同操作相同字节返回原结果，不同字节返回冲突；账号删除不删除回执，不把旧操作重新解释为新创建。GET 回执重新核验当前账号读取权限和身份摘要，POST 重放还核验当前创建、凭证、调度、网络和业务分组权限。响应不返回原凭证、邮箱或上游身份标识。

IP 分组新增显式全局授权 `proxy-groups.read` 和 `proxy-groups.assign`。分配权限描述明确提示会修改共享 IP 的全局并发、取消绑定账号上限；每个目标账号继续校验当前读取、网络和必要的调度权限，关联影子账号保持完整管理员边界。提交的 `expected_proxy_ids` 在分组锁内与当前完整成员比对。账号绑定与永久幂等回执同事务，回执以稳定 KeyID 隔离，使用保留作用域和无限到期时间，不进入通用缓存重放；旧请求不会覆盖管理员后续修改。

旧迁移、费用、余额、计量、首字、模型调用、并发调度规则和完整管理员分配接口保持。新增表属于加法迁移，旧程序回退不撤销或清除回执表。新旧程序同制品升级/回退仍需实际验证。

## 使用升级版本

接收站升级到包含本协议的正式版本后，由该站管理员在现有受限密钥中配置目标业务分组、OpenAI OAuth 及所需账号权限。需要按 IP 分组分配时，再明确授予上述两个全局 IP 分组权限。种菜重新读取连接选项后展示能力和具体不可用原因，确定性的版本/权限/参数错误停止自动重试。

有明确未发送或被旧接口拒绝的历史失败任务可沿用原操作恢复；既往请求结果未知时先核对原结果，不能换操作 ID 创建重复账号。外部客户自行维护的接收站由其管理员安装本版本；本轮托管部署不代表客户站点已经升级。
