# 账号授权与巡检（PK-036）

目标版本：v0.2.19-pk.9。基线：私库 main / v0.2.19-pk.8，14da35f11e628983eb90b52202726a8721aaa1ba。

## 用户要求与实现边界

- 管理员侧栏在雷达观测站之后新增账号授权：工作台、授权代理、凭据历史三个页签。雷达新增授权巡检页签。
- 使用本项目 OAuth 授权链接及 PKCE 会话；现有 SessionStore 使用独立随机会话和读写锁，可并发生成，无需 CPA 通道。
- 保留授权并发、账号并发、账号优先级和入库分组。新账号负载因子等于账号并发；重授权保留原账号配置、代理、分组和二开 extra。
- 每次巡检重新读取账号管理中的 OpenAI OAuth 账号。复用原生连接测试向官方发送 hi；重授权触发状态码可配置，默认401，支持多个400至599错误码。账号管理已有匹配错误码时不重复探测；新响应按同一份配置判定。
- 巡检和重授权由同一服务端 cron 调度，默认每3分钟巡检、每10分钟重授权。巡检结束后按邮箱查找最近提交的密码和2FA；缺少凭据明确展示，不能创建替代账号。
- 授权代理独立于账号请求代理。每次授权先通过选中的出口 GET chatgpt.com；失败不回退直连。代理、密码、2FA 加密存储，普通列表与日志不返回秘密。
- 官方登录使用独立浏览器会话完成密码和 TOTP；验证码/人工验证不能误报成功。校验 OAuth state、回调地址、邮箱与账号身份后才应用凭据。
- 仅新增独立功能表，不删除或回填旧数据。保留现有糖果测试、转组、计费、缓存转换、Kilo开关及管理员权限。

## 实施顺序

1. 账号凭据、代理、任务、巡检状态的持久化与管理员 API。
2. 原生探测适配、cron 调度、并发授权与安全更新原账号。
3. 工作台及雷达页签、后台生命周期、浏览器运行依赖和维护登记。
4. 静态核对调用链、权限、并发与状态机、最终差异；按项目既定流程提交并推送 main 与唯一新标签。

## 最终行为与静态核对记录（2026-10-31）

- 测智：dispatchRadar每次查询当前accounts及可调度/过期/目标分组条件；原模型并行、完整答案判定及即时转组保持。巡检：每3分钟cron到期重新获取OpenAI OAuth名单，每个请求前重读账号；新增账号进入下轮，删除账号不复活。
- 两类授权定时任务统一从服务端cron派发，保存持久化下次时间。协调器与浏览器队列分别持有数据库会话锁，同类工作不重叠，长登录不占用巡检锁。重授权到期先等当前巡检结束再选择最新账号；无页面计时器触发后台任务。
- 重授权触发码默认401，配置允许不重复的400～599。原生连接探测返回真实HTTP码，错误码匹配与已确认失效使用同一规则，网络失败不会冒充失效。
- 最新邮箱/密码/2FA不完整时不进入自动队列。补全对话框固定已有邮箱，空邮箱可补填；写入追加加密历史并显示已补齐等待下轮，不调用wake或创建任务。排队任务固定选定的history_id，后续补全不替换其快照。
- 参考账号API：account-api.cjs运行run-account.cjs；后者通过官方页面的deleted/deactivated文字识别封禁。credits-protocol.cjs从error.code及官方/error页面payload识别account_deactivated。新实现覆盖页面、授权API响应、错误页、有效state回调及令牌交换明确错误；不将裸401/403、代理失败或Cloudflare挑战作为封禁。任务独立banned终态、凭据历史同邮箱封禁标签/筛选、巡检已存在账号封禁态均保留；不自动反复授权，手动处理后成功才清除显示。
- 每次授权先用选中代理GET预检chatgpt.com；本机仅建回环CONNECT桥支持SOCKS认证，未配置/失败不直连兜底。浏览器独立profile并清理；页面只向允许的官方登录和资源域名发请求，凭据只填官方登录页。
- 身份、邮箱、原ChatGPT工作区、任务owner、取消与配置在应用凭据前校验；使用原生账号事务更新与分组准入，保留已有二开extra/分组/并发/代理。系统错误停调在成功后恢复，inactive手动停用保持。配置与账号锁顺序一致，成功后更新token缓存与调度快照/outbox。
- 最终静态修正：封禁响应正文读取与恢复浏览器响应使用独立超时预算，正文读取超时不阻断页面继续；原生ListAllWithFilters与GetByID保持相同事务作用域，授权事务内重复邮箱查询不再另占数据库连接。
- 新增迁移253的五张独立表，无旧结构变更。普通列表与任务只保存安全状态，不包含秘密；历史查看使用step-up。提交/补全/代理正文不进审计，操作元数据仍保留；固定TOTP_ENCRYPTION_KEY后才可保存秘密，避免临时密钥重启丢失。
