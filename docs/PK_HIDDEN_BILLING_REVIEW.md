# PK-029 隐藏倍率核对

基于私库 `f0671148bc54d87a95623035e23a94ad5c74be0e`（上游 v0.2.16 / PK-028），目标分支 `codex/v0.2.16-pk.2`。本次是独立功能开发，不合并新上游，不构建发行包或更新生产。

普通请求示例：原始费用1、分组1.5、隐藏2，实际扣3；用户专属倍率0.4时替代分组1.5，实际扣0.8。管理员可见原始费用及三项倍率；普通用户基础费用展示为2、分组倍率0.4、实际费用0.8，不收到隐藏倍率字段。默认1保持原客户账单。数据库保存当时的隐藏倍率，之后修改账号不影响旧账。

## 验证证据与边界

源码验证使用用户指定测试服务器的独立DinD环境及临时PostgreSQL/Redis，执行完整 `scripts/test-server.py`。仅当报告为 `passed` / `source_eligible=true` 且暂存tree一致时提交，再绑定 `refs/notes/pk-source-validation`。实际结果、tree、命令、原始日志SHA256和跳过项以最终PR及该提交notes为准，本文列出覆盖范围，不替代运行报告。

扩展仓库原有测试文件，不创建遗留临时测试文件。本机仅编辑/格式化/静态检查，没有运行本地构建或测试；发行制品构建和线上操作不在本次范围，未使用真实第三方付费请求作为验收。

批量图片保留上游账号倍率、独立图片倍率及批量折扣；管理员展示的“分组/专属”是本笔应用的倍率（可能含高峰或折扣），原始费用是隐藏与该倍率应用前的计费基数。Free Fast、原上游长上下文边际定价等特殊规则继续由原定价器决定，不能用简单三数乘法反推替代它们。预留是保守估算，不承诺等于最终账单。

## 2026-10-16：下游 Token 用量应用隐藏倍率

用户明确要求所有返回下游的Token用量乘隐藏倍率，不增加可见倍率字段。本轮基于私库 `ec35f1e77edbaeb429033a01a3c5a151959964f8`，复用上游 v0.2.16，目标版本分支 `v0.2.16-pk.5`；按用户已明确的命名要求不再创建codex前缀。无新增PK ID，扩展PK-005、006、029，保留PK-030原始趋势。

处理顺序为：采集上游原始用量 → 原有缓存转换 → 对最终客户端副本乘隐藏倍率。内部计费仍只按原有隐藏计费桥乘一次；不能从已缩放的JSON/SSE/WS副本重新采集费用或原始图表。普通输入、输出、缓存及图片/音频/推理Token明细使用decimal向下取整；总数依照原字段的组成关系与残差重算，避免缓存和推理子集重复计数。倍率1原字节保持；0显式清零；不增加任何倍数字段。

|---|---|
| PK-001～004 | 缓存转换顺序、价格/长上下文、隐藏计费一次和原账务保持；原网关计费/预留/数据库用例继续执行。输出后原始byte slice不可变。 |

覆盖的HTTP入口包括OpenAI/Kilo、Anthropic/Bedrock、Gemini/Antigravity、SystemOne、图片和embeddings；真正OpenAI/Grok WS及本站代理的Live Sideband控制帧在最后发送处处理，连接建立时冻结倍率，原读帧及Live零费用记录不改。异步图片worker在独立recorder中变换并保存，poll不重复变换；输出改写失败使用专用状态标记任务Failed/502，即使已有HTTP200空白心跳也不能把错误JSON当成功结果。Gemini缓存list/get每个账号在单次请求只查询一次倍率，存储记录及续期计费不修改。
