# pk.66 BPS 自动授权修复

## 问题与范围

2026-11-15 用户在生产排查后要求修复 BPS 自动授权。只读证据表明：已保存账密的合格账号创建了 Excel 授权任务，但一直 queued、attempt=0；内置凭证进程未运行。授权运行器用完整 PK/HA 版本查询上游发行资产，返回 404，本项目正式发行也未包含该独立运行包。另一个阻断是 HA worker-only 不监听 HTTP，而内置凭证进程必须回连同实例的内部协议接口。

本次沿用 PK-017/021/047/050/051/061，无新业务功能 ID、数据库迁移或计费变更。用户授权修复现有服务，包含配套构建、定向与隔离制品验证、正式发行和逐节点更新；停调账号及自动策略范围保持既有配置。未完成阶段不得写为已上线。

## 行为与交付

- 授权运行包固定从本项目发行来源取得。程序编译时绑定正式版本、架构和 SHA256；HA 程序显式绑定相同正式运行包，不再拼接 HA 版本查上游。
- 允许预置同一归档，先校验再执行。已安装缓存按校验通过的归档核对全部成员，拒绝替换、链接和额外文件；不伪造 ready 标记。
- 正式发布校验要求运行包、源码输入描述与同程序隔离验证证据，旧封存包继续按旧规则核验。HA 构建也强制新版本携带运行包绑定。
- HA worker 只在回环地址开放内部凭证协议允许列表，保留逐请求 token 和任务所有权校验。管理页面与业务请求不能借此入口访问。
- 正常退出先停止凭证生产者和领取，等待已经领取的授权及回调完成，再关闭 HTTP。原进程意外退出的后代清理保持；不能用强杀冒充正常排空。
- 后台正常退出预算提高到 1800 秒，覆盖最长 25 分钟授权与结果入库；监督器、更新器及 systemd 契约一致，超时仍停止更新，不强杀。
- 凭证运营在 API 副本读取活动后台的限时状态，心跳只含固定状态和原因。旧 owner 不可覆盖或删除新 owner；Redis 诊断失败不修改账号或授权任务。排队数量和等待时间按当前列表真实数据展示。
