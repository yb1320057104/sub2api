## 最终业务规则

- 工作台仅选择及格分组，支持多选。不及格目标显示既有糖果测试设置中的“不合格账号移入分组”，可直接打开同一设置弹窗；后端不接受工作台另传的不及格目标。
- 提交时保存模型/推理强度及及格目标；要求糖果设置中存在有效的不及格目标。真正转组时重新读取并锁定当前糖果设置，因此中途调整后的不及格目标会生效。
- OAuth 凭据校验成功后保存到原账号或新账号，清空分组并停调，然后执行一次既有糖果测试。完整答案21及格，其他完整答案不及格；网络、协议、不完整回复及取消不判答错。新账号负载因子与账号并发一致。
- 及格进入工作台所选的全部及格分组；不及格只进入糖果测试当前配置的目标分组。转组前锁定并校验组存在、启用、OpenAI平台、OAuth类型及隐私准入；保留原生简单模式与混合渠道检查。账号凭据、代理、分组或状态被人为改动时不覆盖。
- 完整测智判定先独立保存，分组与任务完成再一并提交。准入失败、取消、中断仍保留授权已保存和测智判定；未完成分组的账号维持无组停调。手动禁用不自动启用。
- 定时重授权与旧排队任务不套用新工作台关卡，保留原账号分组、并发、负载、优先级、代理及二开配置。
- 巡检每轮获取最新账号列表，执行前再次读取。只同步账号管理的状态；不再发送hi，不再写accounts错误或停调状态。默认error401，可配400～599；旧巡检expired不能让当前active账号重新排队。
- 仍保留3/10分钟cron、并发、加密历史、缺凭据补全后等下轮、管理员与敏感历史step-up边界。未改表结构。

## 2026-10-31 追加：Cloudflare 自动验证（Kilo 同款逻辑）

用户要求参照其本机 `kilo登录` 项目（V41 移植版，`patchright` + Chrome 通道）把 CF 挑战纳入授权流程，并用其提供的正常账号实测。

### 实现要点（`backend/internal/service/account_authorization_browser.go`）

1. **身份不裸奔**：新增 `--disable-blink-features=AutomationControlled` 等启动参数；`Page.addScriptToEvaluateOnNewDocument` 抹掉 `navigator.webdriver` 并补齐 `window.chrome`；`Network.setUserAgentOverride` 的 `userAgentMetadata` 填实原先为空的 `platformVersion`，只有真实 Chrome 通道才追加 `Google Chrome` 品牌，Chromium 不自称 Chrome。
2. **先无头、后真人浏览器**：`PK_AUTH_BROWSER_MODE` 可选 `headless` / `background` / 留空（默认按 Kilo 顺序）。挑战类失败不重放凭据，而是换下一个身份：同一代理、同一账号、全新临时 profile，起真实 Chrome 窗口并移到 `-32000,-32000` 屏幕外。
3. **Linux 自动 Xvfb**：后台会话需要图形环境，`DISPLAY` 缺失且存在 `Xvfb` 时在 `:90`～`:99` 里挑空闲号自启私有 Xvfb，进程随该次尝试结束回收；`deploy/install-browser.sh` 同步改为 `apk add --no-cache chromium xvfb` 并校验 `/usr/bin/Xvfb`。
4. **挑战不再等于失败**：`cf-mitigated: challenge`、`Just a moment...`、可见的 `challenges.cloudflare.com` iframe 一律按“挑战中”处理。`authorizationChallengeProbe` 取组件矩形，`authorizationChallengeClick` 用 `Input.dispatchMouseEvent` 派发真实鼠标按下/抬起（坐标沿用 Kilo 的 `x+28, y+min(30, h/2)`，最多每 8 秒点一次），`authorizationPassChallenge` 轮询到页面恢复为止。无头窗口 30 秒、后台会话 150 秒。
5. **挑战清除后恢复**：登录页被挑战文档替换时，点击通过后重新打开同一授权链接续跑，最多 2 次；预检阶段被挑战则通过后重新导航 chatgpt.com 再判定。
6. **凭据安全边界不变**：`authorizationBrowserError.noReplay` 在密码/2FA/授权确认已提交后为真，此类失败直接终止，不换身份、不换出口、不二次提交；`proxy_challenge` 与登录期安全验证保持 `needsInput` 语义，裸 401/403 仍不判封禁。
