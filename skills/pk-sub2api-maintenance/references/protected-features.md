# 二开清单定位与登记

本 skill 不再复制功能明细。唯一登记表是当前私库工作区根目录的 `PK_FEATURES.md`，项目规则为同目录的 `PROJECT_CONSTRAINTS.md`，入口为 `AGENTS.md`。

## 读取方式

1. 定位正在操作的可信 `yb1320057104/sub2api` 工作区，优先读取这三个文件；安装 skill 的目录不是项目根目录，不能把 `../../..` 当成当前 checkout。
2. 浏览入口：[二开清单](https://github.com/yb1320057104/sub2api/blob/main/PK_FEATURES.md)、[项目约束](https://github.com/yb1320057104/sub2api/blob/main/PROJECT_CONSTRAINTS.md)。私库访问使用已有合法授权，不能因匿名访问失败改用作者仓库。
3. 工作区缺文件时，从可信私库分支/提交获取并核实当前约束。旧备份/旧标签中没有清单不代表没有二开；不能凭本 skill 或历史清单重写代码冒称恢复完整。

## 执行要求

- 遵守当前 `PROJECT_CONSTRAINTS.md` 第 6 节：工作分支使用 `vX.Y.Z-pk.N`，禁止任何附加前缀，同一目标未发布版本的所有工作复用一个分支和 PR，默认仅一个在途版本；不同版本并行须用户明确要求。新建前先查本地/远端分支、在途 PR、私库标签，未明确版本不先建临时分支，不追加任务、日期、助手或功能后缀。分支命名不代替二开保留、静态核对和制品验收。
- 2026-10-21 用户授权清理本地与私库所有带前缀旧分支；先确认提交已保全、无在途 PR/Jenkins/worktree 引用再删除，不丢弃独有工作。Jenkins 可信 SCM 及初始化固定使用 `main`，Git 命名空间和作者仓库上游分支不在清理范围内。
- 清单覆盖账号缓存转换、账务与 usage、首字设置与权限、私库更新/回退、Docker 持久化、并发和后台交接等；具体行为以当前清单和实际代码共同核对，不将此概览当成完整范围。
- 合并上游逐个有效 PK ID 记录“已保留 / 无影响 / 待验证”及依据；检查新调用路径、协议、导出和数据字段，不能只检查清单中的旧文件名。
- 新二开必须在同一变更添加 ID 和完整条目；已有二开扩展、修复、移动文件时更新原条目。发现未登记的已有能力也必须补齐保护。
- 用户明确要求改变某项行为时，保留 ID 和变更依据；合并上游本身不授权改变二开。实际功能冲突、功能缺失或清单遗漏须先处理；“待验证”要区分未解决的行为问题与仅未运行可选测试，不能把后者重新变成强制源码测试门禁。
- 2026-10-21 用户取消完整源码测试和 validation notes 对直接提交、推送、合入 `main` 及正式 `release` 的前置要求，覆盖 2026-10-08、2026-10-19 的相关旧规则。默认完成二开保留、静态核对和清单同步后直接提交推送，不自动执行完整源码测试，不强制绑定 notes，不因缺少报告追加审批。可选测试未运行、失败、部分执行或取消均如实记录，不伪造通过。
- 正式交接推送私库 `main` 历史内未占用的 `vX.Y.Z-pk.N` 标签并核对远端指向；显示及 Jenkins `SOURCE_REF` 不带 `origin/`，用户手动选择 `ACTION=release`，`COMMIT_SHA`、`PACKAGE_ID` 留空。新 Jenkins 不要求源码 notes，但继续执行十一项制品运行时验收、SHA256、私有来源与不可覆盖标签检查；已有封存包及历史源码证据保持完整。
- 源码测试工具保留，仅在用户要求时执行；本地不编译发行包，发行构建仍由 Jenkins 完成。区分既有测试、实际本地或服务器执行、Jenkins 制品验收和历史证据。测试被改名、删除或没有纳入选择范围时，不能拿零匹配的成功结果证明行为保留；临时测试文件/夹具用完删除，仓库原有回归保留。

提交说明遵循项目的 PR模板；授权直接提交也须写出受影响/新增 ID、清单同步情况与实际验证结果。不要再在 skill 内创建另一份功能清单，避免新功能只更新了一处。
