# 二开清单定位与登记

本 skill 不再复制功能明细。唯一登记表是当前私库工作区根目录的 `PK_FEATURES.md`，项目规则为同目录的 `PROJECT_CONSTRAINTS.md`，入口为 `AGENTS.md`。

## 读取方式

1. 定位正在操作的可信 `pengkang0322/sub2api` 工作区，优先读取这三个文件；安装 skill 的目录不是项目根目录，不能把 `../../..` 当成当前 checkout。
2. 浏览入口：[二开清单](https://github.com/pengkang0322/sub2api/blob/main/PK_FEATURES.md)、[项目约束](https://github.com/pengkang0322/sub2api/blob/main/PROJECT_CONSTRAINTS.md)。私库访问使用已有合法授权，不能因匿名访问失败改用作者仓库。
3. 工作区缺文件时，从可信私库分支/提交获取并核实当前约束。旧备份/旧标签中没有清单不代表没有二开；不能凭本 skill 或历史清单重写代码冒称恢复完整。

## 执行要求

- 遵守当前 `PROJECT_CONSTRAINTS.md` 第 6 节：新工作分支使用 `codex/vX.Y.Z-pk.N`，同一目标未发布版本的所有工作复用一个分支和 PR，默认仅一个在途版本；不同版本并行须用户明确要求。新建前先查本地/远端分支、在途 PR、私库标签，未明确版本不先建临时分支，不追加任务、日期、助手或功能后缀。分支命名不代替原审核、测试和发布门禁。
- 现有分支本次不删改；`codex/jenkins-build` 继续完成当前固定 Jenkins 流水线的迁移，收尾后按既定流程切到已审阅的 `main`。未来清理先确认已完成该变更既定的合入/发行流程、没有未保全的独有提交、无在途 PR/Jenkins/worktree 引用，再按授权操作，不强制删除。
- 清单覆盖账号缓存转换、账务与 usage、首字设置与权限、私库更新/回退、Docker 持久化、并发和后台交接等；具体行为以当前清单和实际代码共同核对，不将此概览当成完整范围。
- 合并上游逐个有效 PK ID 记录“已保留 / 无影响 / 待验证”及依据；检查新调用路径、协议、导出和数据字段，不能只检查清单中的旧文件名。
- 新二开必须在同一变更添加 ID 和完整条目；已有二开扩展、修复、移动文件时更新原条目。发现未登记的已有能力也必须补齐保护。
- 用户明确要求改变某项行为时，保留 ID 和变更依据；合并上游本身不授权改变二开。功能缺失、清单遗漏或受影响项待验证时不合入/发布。
- 区分已存在测试、当前 CI 实际执行、历史远端验收。测试被改名、删除或没有纳入选择范围时，不能拿零匹配的成功结果证明行为保留。

提交说明遵循项目的 PR模板；授权直接提交也须写出受影响/新增 ID、清单同步情况与实际验证结果。不要再在 skill 内创建另一份功能清单，避免新功能只更新了一处。
