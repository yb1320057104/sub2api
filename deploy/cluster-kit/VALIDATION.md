# 工具包 0.1.0 验证记录

本包用于全新独立站点，不是既有生产集群重装或迁移脚本。以下是本轮实际执行范围。

## 已完成

- 固定 Git 源与归档输入均完成准备；4,661 个基线文件、94 份源码改动、最终 4,681 文件哈希核对通过，保留全部 324 SQL 迁移。重复执行校验通过；3 项归档安全和防覆盖检查通过。
- 14 份 YAML 解析、33 个 single/primary/secondary/arbiter 模板在 StrictUndefined 模式下渲染通过；10 项配置错误及不覆盖原文件检查通过。
- 应用模板和 worker 状态机 10 项、存储配置和 RESP 解析 5 项本地检查通过。
- Linux Python 3.12 / Ansible 2.18.5 隔离容器中，部署与状态检查两份 playbook 语法检查通过。
- 实际 Docker Compose 校验 7 份配置通过；Caddy 2.8.4 校验 3 份配置通过；HAProxy 3.0.5 校验 2 份配置通过。
- 隔离 PostgreSQL 18.1 成功创建新数据库与应用角色，真实应用密码连接确认可写、角色上限 90、总连接上限 100。该测试为节约资源将 shared_buffers 从模板 512MB 降至128MB，没有变更初始化 SQL。
- 隔离 Redis 7.4.2 通过真实密码 PING 与 master 角色检查。
- Patroni 4.1.5 镜像实际构建成功；在一个无公网出口的独立网络命名空间内，启动3个真实etcd成员形成健康仲裁后，Patroni 原生配置校验通过。所有临时数据库、Redis、仲裁及校验容器均已移除。

Linux 配置检查使用独立临时容器，未开放宿主端口，未挂载生产数据库、账号或配置。
第一次测试依赖在线安装因测试容器 DNS 不通失败，随后以本机下载的同版本 wheel 离线安装通过；该失败未导致修改线上网络。
Patroni 最初在无仲裁的 network-none 中因 etcd 不可达拒绝验证；Docker internal bridge 夹具创建也因测试宿主缺少对应防火墙链失败，未修生产防火墙。改为独立 network-none 命名空间配置测试地址，并给etcd足够的临时WAL空间后通过；早期失败记录保留。此实验在单台宿主完成，不冒充三台新主机或WireGuard端到端验收。

## 验证边界

- 未在三台全新 Ubuntu 主机执行完整 Ansible 安装，未演练新站的宿主断电、网络分区或公网 DNS 接管。
- 未重新构建完整前后端应用镜像。本包提供的源码与 HA r4 修复链按文件核验一致；Docker 构建会重新执行 manifest 中的定向测试。现有 r4 生产验证不能冒充新镜像构建结果。
- Caddy 检查为实际配置装载；没有给示例域名签发证书。真实部署必须有正确 DNS、可达的80/443和有效域名。
- 未发送真实模型、账号授权或糖果请求；不消耗账号额度。
- 未触发 GitHub Actions、Jenkins 或普通应用发行；未替换或重启现有生产服务。

这是经过配置和核心初始化验证的首版部署工具包。首次正式使用应先选择独立测试服务器完成全流程验收；不能据此承诺任意服务器环境均无需调整，或承诺故障切换零数据损失。
